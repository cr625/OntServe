## Question 2. Behaviour the rule does not name

### Findings with a fix, applied on the review branch

1. `tools/backfill_base_uri.py:91` and `services/ontology_sync_service.py:49` (`declared_base_uri`). Scenario: a case row whose `base_uri` was set by hand (the settings page, `http://example.org/custom#`) or by the draft route (`http://proethica.org/ontology/proethica-case-8`, no `#`, `web/draft_routes.py:112`) differs from the declared IRI as well, so the dry run listed it as `-> http://proethica.org/ontology/case/8` and a write run rewrote it, while the re-sync rule of the same commit leaves such a value alone. The dry run also assigned the new value to the row before the rollback. Fix: the decision rewrites only a row whose `base_uri` is the file-name pattern (`default_base_uri`, now module-level) and reports `hand-set base_uri kept` otherwise; the dry run assigns nothing. The listed rows are exactly the pattern-valued rows whose content declares another IRI. Tests: `test_declared_base_uri_keeps_a_hand_set_value`; `tests/unit/test_backfill_base_uri.py` runs the script's dry run, write run, `--all` and `--name` against a fake session (the script is imported with a placeholder `ONTSERVE_DB_URL`, since `web/app_config.py` reads the variable at import; nothing connects, `make_app` is replaced).

2. `servers/reasoning_tools.py:166` (`reasoning_checks`, the domain and range block). Scenario: a property whose `rdfs:domain` or `rdfs:range` is an anonymous `owl:unionOf` class was skipped (only `URIRef` objects were read), so the Checks block under-reported the constraints Pellet verifies: `core:initiates`, `core:terminates`, `core:establishedBy` (domain) and `core:establishes` (range) in proethica-core, `proeth:temporalMarker`, `temporalSequence`, `hasTemporalRelation` (domain) and `fromEntity`, `toEntity` (range) in proethica-intermediate. Fix: `_class_expr_iris` lists the named members of a union (the panel joins them with ` | `, so the domain reads "Action | Event") and marks another anonymous expression `(anonymous class expression)`. Test: `test_checks_list_union_and_anonymous_domain_constraints`.

3. `services/ontology_sync_service.py:28` (`ontology_iri_from_graph`). Scenario: with several `owl:Ontology` declarations the first IRI in sorted order was taken. `ontologies/engineering-ethics.ttl` declares `.../engineering-ethics` and `.../engineering_standards`, and the sorted order picks the file's own IRI there only because `-` sorts before `_`. A file whose secondary declaration sorts first would get that IRI as `base_uri` on create and on the re-sync of a pattern-valued row, and its header metadata would be read from that declaration (the same commit restricts the header read to the IRI-bearing declaration). Fix: the declaration whose local name equals the file stem (the ontology name) is preferred, else the sorted order; `_extract_ontology_meta` passes the stem and `declared_base_uri` the ontology name. Tests: `test_several_declarations_prefer_the_one_named_like_the_file`, `test_extract_ontology_meta_reads_the_header_of_the_preferred_declaration`.

### Points without a change

4. `_extract_ontology_meta` (`services/ontology_sync_service.py:182`) reads the header fields from one declaration now; before, every `owl:Ontology` subject was visited and the last one won per key, in the iteration order of rdflib. For engineering-ethics the title and the source came from the `engineering_standards` declaration and are no longer read; the stored values stay (`HEADER_META` writes a value only when present). The change removes a nondeterministic merge; a one-declaration file is unaffected.

5. `web/case_display.py:218` (`is_support_node`) reads `properties['rdf_types']` beside `parent_uri`; before, `parent_uri` only. A row whose secondary type is in the `prov:` or `time:` namespace now goes to the support section and out of the count. The ProEthica emitters type the time anchors `time:Instant` or `time:ProperInterval` only, the one timeline individual `time:TemporalEntity` (support under both rules, that is its `parent_uri`), and no happening or agent with a `prov:` or `time:` class (`app/services/extraction/time_anchor.py`, `timeline_edges.py`, the commit emitters). No row of a ProEthica case changes section.

6. `web/case_display.py:621` (the non-empty filter) and `build_ordered_blocks` drop a section whose only content is bare class redeclarations, chips included; `test_unmatched_bare_class_goes_to_other_types_used` asserts it deliberately. Before, such rows rendered as cards in Other. A case whose Other section held only redeclared classes outside the nine categories and the actor types shows those classes nowhere on the page now. Left as the author's decision; a chips-only block would need the filter, `_section_count` and the macro to accept an empty entity list.

7. `web/entity_extraction.py:663`: the catch-all pass writes `named_individual = False` into the properties of every individual it stores, for every ontology, so a row that stored `properties` NULL (an OBO-style bare resource, an untyped labelled resource) now stores `{"named_individual": false}`. The entity pages hide the key (`display.py` `_SKIP_KEYS`, `entity_display.html`, `entity_display.yaml`); the enrichment table of `ontology_detail.html` (line 1276) tests the truthiness of `entity.properties` and labels such a row "Manual" in place of "Unknown". Cosmetic; `content_hash` is unchanged, so no embedding is recomputed.

8. `web/case_competition.py:65` (`_VERBATIM_SOURCE_FIELDS`, textreferences and sourcetext): the `DefeasibilityEdge` vocabulary of ProEthica (`app/services/extraction/schemas.py:1211`) has seven fields (tensionresolution, balancingwith, constraintstatement, concreteexpression, interpretation, obligationstatement, casecontext), none of them these two, and the defeasibility pipeline is the only emitter that writes a `source_field=` note. Every derivation node of a current case therefore renders "derived from", and a passage renders as verbatim only for a legacy note without a field. The docstring and the panel text describe a verbatim case the emitter never produces; the rendering is right for the rows that exist.

9. `web/case_competition.py:84` (`_source_individual`): the local names of the `prov:wasDerivedFrom` targets are compared with the fragments encoded in the node IRI, which ProEthica sanitizes (`_safe_frag` replaces every character outside `[A-Za-z0-9_]`), so an endpoint whose fragment carries `-` or `.` would pass as the third target. The same scheme already makes `edge_ref` (line 201) miss the node for such an edge, so no hover is shown for it either way (pre-existing). When the source field belongs to the object endpoint the emitter adds no third target (the triple exists already) and the fallback names the subject; the graph does not carry the distinction, a dedicated predicate on the ProEthica side would.

10. `config/case_display.yaml:30` and `PAGE_BLOCK_ORDER` (the ordering of the agents section): agents is first in both. The formalism panel finds `nine_concepts` by id (`ontology_case.html:555`), the sidebar and the body render `page_blocks` in `PAGE_BLOCK_ORDER`, `get_section_summary` has no caller, and no API route or MCP tool serves the output of `organize_entities_for_case` (`web/ontology_routes/detail_routes.py:187` is its only caller). `all_concept_types` gains `Agent` and `DeliberativeBody` for the suffix match of `match_entity_to_concept_type`; no class in the shipped ontologies ends in either (only the property names citedByAgent, responsibleAgent, hasAgent, decidedByAgent). The engineering domain inherits the default sections, so the section reaches the ProEthica cases. Verified, no change.

11. `web/case_display.py:825` (`build_type_label_index`) identifies case rows by the `proethica-case-` prefix; the rest of the code uses `CASE_NAME_RE` (`^proethica-case-(\d+)$`) or the LIKE pattern of `_base_superclass_map`. Equivalent for the names in use.

12. Legacy rows (`is_named_individual` fallback): an `individual` row without the flag and without a type (an untyped labelled resource) counts as a named individual until its ontology is re-extracted, after which it carries False. Transitional, and such rows are rare in case graphs.

13. The reasoning checks list the characteristic-property pairs of the target only; pairs asserted in the imported vocabularies are examined by Pellet but not reported, by design ("that the target asserts at least one pair for").
